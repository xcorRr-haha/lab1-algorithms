# Описание лабораторной работы

**Цель:** Реализовать 4 алгоритма поиска и выяснить, какой из них эффективнее в зависимости от размеров массивов.

## Структура проекта

- `src/algorithms.py` — 4 алгоритма (два указателя, бинарный, экспоненциальный, двойной бинарный)
- `src/generator.py` — генерация тестовых данных (числа разной четности с равномерным распределением)
- `src/benchmark.py` — замеры времени и сохранение результатов
- `src/plot.py` — построение графиков по полученным данным
- `tests/test_algorithms.py` — тесты на корректность работы
- `data/results.csv` — сырые данные замеров
- `plots/` — сгенерированные графики

## Запуск

Для установки зависимостей и запуска выполните следующие команды:

```bash
pip install -r requirements.txt
python tests/test_algorithms.py
python src/benchmark.py
python src/plot.py
```
## Методика замеров

Для тестирования генерировались массивы разной четности: в одном только четные числа, в другом — только нечетные. Числа распределялись равномерно по всей длине массива. Это создает «худший случай», когда общих элементов нет, и алгоритмы вынуждены просмотреть все элементы до конца.

Время замерялось с помощью time.perf_counter(). Чтобы отсечь случайные зависания операционной системы и фоновые процессы, для каждой точки графика делалось 100 замеров (для больших массивов — 10), после чего вычислялось среднее арифметическое. Перед замерами выполнялся «прогрев» (один холостой запуск), чтобы исключить влияние первичной загрузки в память.

## Анализ результатов

**1. Массивы одинакового размера (M = N)**
<img width="1350" height="750" alt="equal_sizes" src="https://github.com/user-attachments/assets/e86871c5-cb80-4c30-89fb-ceabe2e060b4" />

При равных размерах массивов два указателя и бинарный поиск показывают близкие результаты. Два указателя делают один линейный проход, а бинарный поиск делает 
M
M логарифмических поисков. Экспоненциальный и двойной бинарный немного проигрывают из-за накладных расходов на дополнительные вызовы и рекурсию.

**2. Сильно асимметричные массивы (M = 100, N растет)**
<img width="1350" height="750" alt="fixed_m" src="https://github.com/user-attachments/assets/2502f97c-0c36-4c9f-8081-3a7d63683c9e" />

Здесь видна классическая картина: два указателя (оранжевая линия) резко уходят вверх, так как алгоритм вынужден шаг за шагом проходить огромный массив N. А бинарный поиск (синяя линия) и экспоненциальный (красная) остаются внизу, потому что логарифмическое деление позволяет им очень быстро находить нужные элементы в большом массиве.

**3. Зависимость от соотношения N / M**
<img width="1350" height="750" alt="varying_ratio" src="https://github.com/user-attachments/assets/086b1125-a071-47f5-8679-236d0e4af4f2" />

График показывает точку перелома: при увеличении отношения N/M (когда один массив становится в разы больше другого) время работы бинарных алгоритмов резко снижается по сравнению с двумя указателями. Это подтверждает теоретические сложности: O(M log(2N/M)) для бинарных алгоритмов и O(M + N) для двух указателей.

## Выводы

- **Два указателя** — лучший выбор, когда массивы сопоставимы по размеру (N/M≤5). Сложность O(M+N), память O(1).

- **Бинарный поиск** — эффективен при сильной асимметрии массивов (когда один массив значительно меньше другого). Сложность O(M logN), память O(1).

- **Двойной бинарный** — показывает отличное время при сильной асимметрии, но требует O(log M) памяти из-за рекурсии.

- **Экспоненциальный поиск** — в данной реализации уступает обычному бинарному из-за накладных расходов, но теоретически имеет хорошую асимптотику O(M log(2N/M)).
